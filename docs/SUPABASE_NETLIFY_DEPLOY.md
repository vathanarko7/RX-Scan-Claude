# RxScan Deployment Guide

This app is now wired for:

- Supabase Auth for staff login
- Supabase Postgres for shared inventory data
- Supabase Realtime for multi-device sync
- Netlify for static hosting

## 1. Create a Supabase project

1. Create a new project in Supabase.
2. Open `Project Settings` -> `API`.
3. Copy:
   - `Project URL`
   - `anon public` key

Official docs:

- https://supabase.com/docs

## 2. Create the `medications` table

Open the SQL Editor in Supabase and run this:

```sql
create table if not exists public.medications (
  id bigint generated by default as identity primary key,
  name text not null,
  generic text default '',
  barcode text not null unique,
  category text not null default 'Other',
  price_box numeric(10,2) not null default 0,
  units_per_box integer not null default 1,
  stock integer not null default 0,
  reorder integer not null default 10,
  zone text not null default '',
  shelf text not null default '',
  expiry date,
  mfr text default '',
  created_at timestamptz not null default timezone('utc', now()),
  updated_at timestamptz not null default timezone('utc', now())
);

create or replace function public.set_updated_at()
returns trigger
language plpgsql
as $$
begin
  new.updated_at = timezone('utc', now());
  return new;
end;
$$;

drop trigger if exists medications_set_updated_at on public.medications;

create trigger medications_set_updated_at
before update on public.medications
for each row
execute function public.set_updated_at();
```

## 3. Enable Row Level Security

Run this SQL:

```sql
alter table public.medications enable row level security;

create policy "Authenticated staff can read medications"
on public.medications
for select
to authenticated
using (true);

create policy "Authenticated staff can insert medications"
on public.medications
for insert
to authenticated
with check (true);

create policy "Authenticated staff can update medications"
on public.medications
for update
to authenticated
using (true)
with check (true);

create policy "Authenticated staff can delete medications"
on public.medications
for delete
to authenticated
using (true);
```

This setup makes the inventory shared across all signed-in staff accounts.

Official docs:

- https://supabase.com/docs/guides/database/postgres/row-level-security

## 4. Configure email/password login

In Supabase:

1. Go to `Authentication` -> `Providers`.
2. Make sure `Email` is enabled.
3. Decide whether to keep `Confirm email` on.

Recommended for a small internal staff app:

- If you want the easiest setup, turn email confirmation off.
- If you want stricter onboarding, leave it on and confirm each staff email.

Supabase auth reference:

- https://supabase.com/docs/reference/javascript/auth-signinwithpassword
- https://supabase.com/docs/reference/javascript/auth-signup

## 6. Deploy to Netlify

This project is a static site, so there is no build command required.

### Easiest method

1. Zip or upload the project folder containing `index.html`.
2. In Netlify, create a new site.
3. Deploy the folder as a static site.

If you later connect a Git repo, the settings are typically:

- Build command: none
- Publish directory: `.`

Netlify docs:

- https://docs.netlify.com/site-deploys/manage-deploys/
- https://www.netlify.com/pricing

## 7. Add your Netlify URL to Supabase Auth

After the first deploy, copy your site URL, for example:

```text
https://your-site-name.netlify.app
```

Then in Supabase:

1. Open `Authentication` -> `URL Configuration`.
2. Set the `Site URL` to your Netlify URL.
3. Add it to allowed redirect URLs as well.

This is especially important if email confirmation is enabled.

## 8. Test shared sync

Use this checklist:

1. Sign in on desktop.
2. Add or edit a medication.
3. Sign in on phone with another staff account.
4. Open Inventory and confirm the change appears.
5. Update stock on one device and watch the other device refresh automatically.

The app auto-seeds sample medications the first time an authenticated project has an empty `medications` table.

## 9. Important notes

- All authenticated staff currently share the same inventory.
- The app uses the public anon key in the browser, so RLS policies are essential.
- Supabase documents backups at the platform level, but Free projects have more limited recovery options than paid production setups.

Official references:

- https://supabase.com/docs/guides/platform/backups
- https://supabase.com/docs/guides/deployment/going-into-prod
